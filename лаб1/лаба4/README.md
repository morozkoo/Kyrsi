# Лабораторная работа № 5

## React-клиент API конвертера валют

React-приложение загружает валюты из собственного Express API и выполняет CRUD-запросы к PostgreSQL. В интерфейсе доступны регистрация, вход, просмотр профиля, поиск и сортировка. Для изменения справочника требуется JWT пользователя с ролью `admin`.

Валютный справочник включает BYN — белорусский рубль (`Br`). При создании или редактировании символ можно выбрать из сетки популярных обозначений либо ввести свой.

## Запуск

Сначала из корня серверного проекта запустите PostgreSQL и примените миграции. Для самого первого заполнения базы запустите seed один раз, затем запустите API:

```bash
npm run db:migrate
npm run db:seed
npm run dev
```

Если таблица `currencies` уже содержит данные, пропустите `npm run db:seed`: текущий seed добавляет исходные строки напрямую и при повторном выполнении может получить ошибку дубликата ключа.

В отдельном терминале перейдите в каталог `лаба4`, установите зависимости и настройте адрес сервера:

```bash
cd лаба4
npm install
```

Скопируйте `.env.example` в `.env`. По умолчанию клиент обращается к `http://localhost:3001`:

```env
VITE_API_URL=http://localhost:3001
```

Запустите клиент:

```bash
npm run dev
```

Vite обычно открывает приложение на `http://localhost:5173`. Express включает CORS для браузерного клиента; при необходимости разрешенный origin можно задать серверной переменной `CLIENT_ORIGIN`.

## Аутентификация и права

Форма в верхней части страницы позволяет зарегистрироваться и войти. После входа JWT сохраняется в `localStorage` под ключом `currency-radar-token` и автоматически передается в `Authorization: Bearer <token>` для защищенных запросов. Профиль проверяется через `GET /profile`.

Новая учетная запись имеет роль `user`, поэтому она может просматривать список, но не изменять его. Для демонстрации подготовлены учетные записи:

| Email | Пароль | Роль |
| --- | --- | --- |
| `test@gmail.com` | `1` | `user` |
| `admin@gmail.com` | `1` | `admin` |

Создать или повторно восстановить эти учетные записи в подключенной PostgreSQL можно из корня проекта:

```bash
npm run db:seed:demo-users
```

Пароль хранится в БД только в виде bcrypt-хеша. Эти слабые демонстрационные данные предназначены исключительно для локальной учебной работы, не для production.

Чтобы добавить BYN в уже заполненную базу, выполните в корне проекта `npm run db:seed:byn`. Команда обновляет только запись BYN; курс при дальнейшем обновлении с ЦБ РФ будет актуализирован сервером.

Для назначения роли admin другой учетной записи зарегистрируйте пользователя и выполните в PostgreSQL запрос, подставив его email:

```sql
UPDATE users SET role = 'admin' WHERE email = 'admin@example.com';
```

Затем войдите заново. Для администратора появятся создание, изменение и удаление валют, а также обновление курсов из ЦБ РФ. Сервер повторно проверяет роль по базе данных для каждой операции.

## HTTP-операции и состояния

- `GET /currencies` загружает список. Отображаются состояния загрузки и ошибки, при ошибке доступна кнопка повтора.
- `POST /currencies` добавляет строку в UI до ответа сервера. При ошибке строка удаляется.
- `PUT /currencies/:id` обновляет интерфейс до ответа сервера. При ошибке предыдущее значение восстанавливается.
- `DELETE /currencies/:id` сразу убирает строку. При ошибке она возвращается на прежнее место.
- Дополнительное улучшение: запрос списка использует `AbortController` и отменяется при размонтировании компонента или повторной загрузке.

API-сервис находится в `src/api.js`, основной экран — в `src/AppApi.jsx`. Точка входа переключена на новый экран в `src/main.jsx`.

## Проверки

```bash
npm run lint
npm run build
```

Проверка сценариев: открыть клиент, убедиться, что список получен с сервера; зарегистрировать пользователя и войти; без роли admin убедиться, что редактор показывает режим чтения; назначить роль SQL-запросом и войти заново; проверить добавление, изменение и удаление. Для проверки отката можно временно остановить API перед CRUD-запросом. После демонстрации удалить тестовые данные.
